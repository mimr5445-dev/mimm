# نظام الإحداثيات والمفاصل — Rigging System

> **هذا الملف هو المرجع الوحيد لنظام الإحداثيات في الاستوديو.** أي شخصية جديدة يجب أن تلتزم به.

## 1) المساحة المنطقية (Logical Space)

- **الأصل:** `feet` عند `(0, 0)` — الأرض.
- **الاتجاه:** `up` هو `-y` (السالب عمودي)، `+x` يمين.
- **الارتفاع الأساسي:** `baseHeight = 240` وحدة عند `s=1` (يُطابق `rig2d.js` الحالي).
- **المقياس:** `s` يضرب كل الإحداثيات. `s=1` = شخصية كاملة 240px منطقياً، `s=0.7` طفل.
- **الاتجاه:** `facingAxis = +x` (ينظر يميناً افتراضياً). `facing=-1` يعكس أفقياً.

## 2) نقاط الارتكاز (Anchors) — 12 نقطة ثابتة

كل شخصية **يجب** أن تحدد هذه النقاط في `manifest.json: rig.anchors`:

| الاسم | الوصف | مثال إحداثي |
|---|---|---|
| `head` | مركز الرأس | `[3, -208]` |
| `neck` | أسفل الرقبة / أعلى الكتف | `[0, -174]` |
| `shoulder` | مفصل الكتف (نقطة التفرع) | `[0, -174]` |
| `hip` | مركز الحوض | `[0, -100]` |
| `elbowF` | مرفق أمامي | `[9, -137]` |
| `handF` | يد أمامية | `[13, -101]` |
| `elbowB` | مرفق خلفي | `[-7, -136]` |
| `handB` | يد خلفية | `[-9, -100]` |
| `kneeF` | ركبة أمامية | `[6, -50]` |
| `footF` | قدم أمامية | `[3, 0]` |
| `kneeB` | ركبة خلفية | `[-6, -50]` |
| `footB` | قدم خلفية | `[-11, 0]` |

> هذه 12 نقطة هي **الواجهة الوحيدة** بين الهيكل والطبقات. كل طبقة ترتبط بـ `anchor` واحد.

## 3) الطبقات (Layers) وارتباطها

```json
"layers": [
  {"id":"cape", "anchor":"shoulder", "src":"layers/cape.svg", "z": 5, "tint":"#2e3d2e"},
  {"id":"hair", "anchor":"head", "src":"layers/hair.svg", "z": 10}
]
```

- `anchor`: النقطة التي تُلصق بها الطبقة (تتحرك معها).
- `z`: ترتيب الرسم (أعلى = أمام).
- `tint`: صبغة اختيارية.

عند تحريك المفصل، كل الطبقات المرتبطة به تتحرك معه **مع الحفاظ على الإزاحة النسبية**.

## 4) كيف تتحرك الطبقات مع الحفاظ على الهوية

- **الوضعيات (`poses`):** تحدد إحداثيات الـ12 نقطة فقط. الطبقات تتبعها تلقائياً.
  ```json
  "poses": {
    "stand": {"head":[3,-208], "handF":[13,-101], ...},
    "point": {"head":[5,-208], "handF":[68,-172], ...}
  }
  ```
- **التعبيرات (`expressions`):** تعدّل طبقة الوجه فقط (عين/فم/حاجب) دون لمس الجسم.
- **الانتقال:** `blendPose(a,b,k)` يمزج إحداثيات النقاط بـ `ease.inOut(k)` — الطبقات تُرسم بعد المزج، لذا لا تشوه.

## 5) الفروق بين المحركات الثلاثة

| المحرك | كيف تُرسم الطبقات |
|---|---|
| `procedural` | لا طبقات SVG — يرسم بـ Canvas مباشرة (كما الآن في `rig2d.js`) |
| `layered-svg` | كل `src` هو SVG يُحمّل ويُرسم في `anchor` مع `z` |
| `hybrid` | طبقات SVG + خلفية/خامة مولدة ثم مجمدة (نفس واجهة `layered-svg`) |

> المحرك لا يُغير الإحداثيات — فقط طريقة الرسم.

## 6) قواعد الاستخدام لكلود

1. لا تغير إحداثيات `anchors` في مشروع فيديو — هي هوية ثابتة.
2. غيّر `pose` و `expression` فقط.
3. استخدم `V()` و `E.W/H` للمواضع العالمية، و `anchors` للمواضع المحلية.
4. لا تضع قيماً خارج `baseHeight ±20%` — حافظ على النسب.

## 7) التوافق مع `rig2d.js` الحالي

`rig2d.js` الحالي يستخدم نفس الـ12 نقطة بأسماء `head, sh, hip, eF/hF, eB/hB, kF/fF, kB/fB` — الخريطة:

```
manifest head   ↔ rig2d head
manifest shoulder ↔ rig2d sh
manifest hip    ↔ rig2d hip
manifest elbowF ↔ rig2d eF
manifest handF  ↔ rig2d hF
... (نفس المنطق)
```

المحول في `library/engine/character.js` يترجم تلقائياً.
